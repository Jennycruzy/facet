How it works

Three actions, one transaction

The sequence is UseNote → Withdraw → ComputeAndInvoke. It runs inside a proved virtual execution, so the private inputs never reach public calldata. Before 25 August 2026 nobody had executed it.

Run it yourself

  
The whole path is reproducible

  
The official prover image aborts on older AMD hosts because it is compiled
  for a newer CPU. The rebuild is published, and the recipe is in the repo.

  
git clone https://github.com/Jennycruzy/facet
# the transaction prover, rebuilt for Zen 2 — see docs/PROVER.md
docker run -p 3000:3000 ghcr.io/jennycruzy/facet-prover:znver2

# the action builder
npm --prefix packages/sdk install && npm --prefix packages/sdk run check
# 20 Cairo fork tests against live mainnet state
snforge test --workspace







  
What we cannot claim

  
The limits, stated first

  
    
    
  • This is not a new privacy protocol. It uses StarkWare's STRK20
    anonymizer unmodified. The contribution is the funding pattern, the SDK path and the
    first execution of it.
    • 
    
  • We are not the only users of the primitive. Most compute-path calls
    on mainnet belong to other teams' anonymizers.
    • 
    
  • We were not the first to fund a shadow account. Seven mainnet
    transfer_from transactions did it first, the public way — that is the
    comparison in the column above, not a strawman.
    • 
    
  • The demo invoke links this facet to its owner, and that is our own doing.
    The dapp call in the second transaction sends one wei to the owner's own address, because
    it was a smoke test. That single receipt therefore does connect them. The unlinkability
    argument here rests on the funding leg, which is shielded; a real call to a real protocol
    would not carry that artefact.
    • 
    
  • No shadow account has touched a DeFi protocol yet. All 39 mainnet
    invocations target the STRK token. Ours is on Sepolia. Mainnet DeFi is the next step and
    is not claimed here.
    •
